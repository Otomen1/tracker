Authoritative overview: PROJECT_MASTER.md. Technical detail: docs/architecture.md,
docs/schema-migrations.md, docs/dependency-security.md and docs/release-checklist.md.
Use code and those documents together; this is not evidence of a shipped release.

Tracker 1.3.2 / Android build 19 is a local finance application. Web/PWA uses local
browser storage; Android uses an authenticated encrypted app-private vault. No
account, cloud sync, PostgreSQL, Clerk or network API is required. Android has no
INTERNET permission. Protect browser data with the device login/disk encryption.

Logical schema 4 supports bank, cash, ewallet and credit-card accounts. Existing
account IDs and transaction references are preserved. Native container encryption
stays v3 to preserve key/AAD compatibility. An independent pre-v4 encrypted
checkpoint is retained until deliberate erase; previous-write recovery is separate.
Unsupported future formats are rejected, never silently reset or relabeled.

Accounts are transaction sources. Keep their names/kinds and transaction links;
opening balance setup, current balances, total assets, card debt/limits/statements
and due dates are removed. Home shows recorded in/out movements and transaction
counts. Own transfers show each source's movement without adding spending. Source
filters and CSV/PDF source labels make history reviewable. Analytics and goals are
explicitly based on recorded activity. Old financial fields stay only for encrypted
backup compatibility, without deriving balances. Existing IDs/history are unchanged.

Android capture is optional, restricted to approved packages and local. Pending
notifications stay in an encrypted review inbox. Confirmation respects edited
amount/direction. A second notification can be deliberately linked to an existing
transfer. Failed reads/saves/cleanup preserve review items and permit safe retries.

Mobile tabs: Home, Activity, Analytics, Settings. Settings are routed: Accounts,
Capture, Finance, Preferences, Reminders, Security, Backup and About. Native Back
handles keyboard, overlays, settings parents and Home before exit. Dirty transaction
drafts prompt before dismissal; committing actions block repeat taps/dismissal.

Portable backups require a strong password and use authenticated encryption.
Restore previews record counts; old plaintext imports are explicit. CSV/PDF contain
unencrypted records and export through Android share or a browser download. Temporary
native share files are cleaned after sharing. Keep a verified external backup.

Native reminders are generic Android notifications and inexact daily alarms;
permission and battery settings affect delivery. Browser reminders require an open
page. Reminder preferences survive lock without exposing financial notification data.

Release requires the original Android signing key. Install a correctly signed update
over the existing app; never uninstall or clear storage as an update workaround.
Read docs/release-checklist.md for build, upgrade, device and data-preservation gates.
